# 本地 OCR 部署说明

这套本地 OCR 是从「ST 绿色版」项目里抽出来的，核心是 **RapidOCR**——PaddleOCR 的 PP-OCR 模型转成 ONNX 格式、用 **ONNX Runtime** 在本地 CPU 跑。**完全离线、不联网、不消耗任何云 API 额度，结果可复现。**

识别的目标场景是「截图里的英文表格/段落文本」（比如打印预览、分析面板）。如果只是中文/通用文档 OCR，它同样能胜任。

---

## 一、技术栈

| 组件 | 作用 |
|---|---|
| `rapidocr_onnxruntime` | RapidOCR 主包，**自带 PP-OCR 的 ONNX 模型文件**（det 检测 / rec 识别 / cls 方向分类） |
| `onnxruntime` | ONNX 模型推理运行时（CPU） |
| `opencv-python`（cv2） | 图像预处理 |
| `numpy` / `Pillow` | 数组与图像读写 |
| `shapely` / `pyclipper` | 文本检测框后处理 |

模型文件装在 `site-packages/rapidocr_onnxruntime/models/` 下：

```
ch_PP-OCRv4_det_infer.onnx          约 4.7 MB（文本检测）
ch_PP-OCRv4_rec_infer.onnx          约 10.8 MB（文本识别）
ch_ppocr_mobile_v2.0_cls_infer.onnx  约 0.6 MB（文字方向分类，可不用）
```

## 二、安装

### 方式 A：联网安装（推荐，最简单）

要求 Python 3.8+（建议 3.10/3.11/3.12），Windows / Linux / macOS 均可：

```bash
pip install rapidocr_onnxruntime
```

它会自动带上 onnxruntime、opencv-python、numpy、Pillow、shapely、pyclipper 等全部依赖，**不需要单独装 PaddlePaddle**（这是 RapidOCR 相对原生 PaddleOCR 最大的优点——轻、快、好装）。

验证：

```bash
python -c "import rapidocr_onnxruntime; print('OK')"
```

### 方式 B：离线 / 直接复制（已有 ST 绿色版时）

如果机器不能联网，可以从已经打包好的 ST 绿色版的 `_internal` 目录里，把下面这些文件夹原样复制到目标项目的 Python 环境（或打包目录）里：

```
_internal/rapidocr_onnxruntime/   ← 含 models/*.onnx
_internal/onnxruntime/
_internal/cv2/
_internal/shapely/
_internal/pyclipper/
_internal/numpy/
_internal/PIL/
```

> 注意：跨机器复制时，cv2 / onnxruntime / shapely / pyclipper 里有 `.pyd`（编译好的二进制），必须保证目标机器的 **Python 版本相同**（本项目用的是 Python 3.12，64 位），否则可能加载失败。

## 三、快速上手（最小示例）

同目录的 `ocr_demo.py` 就是完整的最小示例：

```bash
python ocr_demo.py 你的截图.png
```

它会输出识别耗时和逐行文本。核心代码就几行：

```python
from rapidocr_onnxruntime import RapidOCR

engine = RapidOCR()
result, elapse = engine("图片路径.png", use_cls=False)
# result 是 [[box, text, score], ...]
```

要点：

- `use_cls=False` 关掉「文字方向分类」，**正立的文本（截图/扫描件）能快一半**，精度不降；
- 返回的 `box` 是四个顶点坐标，`text` 是识别文本，`score` 是置信度；
- 要还原「从上到下、从左到右」的阅读顺序，按 box 的 y 坐标分组、x 坐标排序即可（demo 里已实现）。

## 四、作为 Python 模块使用（带归一化）

同目录的 `local_ocr.py` 是 ST 项目里实际用的封装，加了：

- `available()`：探测依赖是否装好，没装返回 False（方便做「本地 OCR → 云 OCR 兜底」）；
- `ocr_image(path)`：读图 → OCR → 返回文本，失败返回 None；
- `normalize(text)`：把 OCR 常见怪癖归一化（Σ 被认成 ∑/Z/E/M、缺空格、大小写粘连等）。

用法：

```python
import local_ocr

if local_ocr.available():
    text = local_ocr.ocr_image("截图.png")
    print(text)
```

> `normalize()` 里的规则是针对 ST 英文分析文本调过的（比如把 `Σ L`、`STRONGLY UP` 拼回来）。你的项目如果不是这种文本，可以直接用 `ocr_demo.py` 的原始版，或删掉 normalize 调用。

## 五、性能参考（普通办公电脑，纯 CPU）

| 项目 | 实测（i3-12100F 4核8线程，无独显加速） |
|---|---|
| 内存峰值 | 约 300 MB |
| 单张 960×1048 图 | 约 3~7 秒（首次加载模型略慢） |
| 单张 1936×1048 整屏截图 | 约 10~13 秒 |

- 识别精度对**印刷体英文/数字**非常好；手写、严重倾斜、极小字号会下降；
- 不需要 GPU，R5 220 这类老独显也用不上（走 CPU 即可）；
- 模型只加载一次，之后可反复识别多张图。

## 六、常见问题

**Q：中文文件名/路径会不会报错？**
会。直接用 `engine(图片路径)` 内部走 cv2 读图，中文路径可能读不到。稳妥做法是先 `PIL.Image.open()` 再 `numpy.array()` 传给 `engine`（`local_ocr.py` 已经这么做了）。

**Q：识别结果缺空格 / 粘连？**
正常，RapidOCR 对英文的单词间空格有时会漏。要么用 `local_ocr.normalize()`，要么自己按场景加正则。

**Q：想换更准的模型？**
可以。RapidOCR 支持指定 det/rec/cls 三个 onnx 路径，把 `ch_PP-OCRv4` 换成 PP-OCRv5 或自己训练的模型即可。`rapidocr_onnxruntime` 默认就是 PP-OCRv4。

**Q：能不能打包进 PyInstaller？**
能。本项目就是把 `rapidocr_onnxruntime`、`onnxruntime`、`cv2`、`shapely`、`pyclipper` 用 `collect_all()` 打进 onedir 包的，模型 `.onnx` 也会一起带进去。参考 ST 项目的 `ST_大师.spec`。
